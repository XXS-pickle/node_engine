# node-engine 交接文档

> 本文件是 `node-engine` 项目的交接手册，供后续 AI 会话、运维或新协作者快速接手。
> 公开仓库不展示节点来源（用户要求）；本文件同样不重复列出源 URL，具体源列表见 `config/sources.txt`。

## 1. 项目概述

基于 `735754647/Free-Nodes` 改造的**免费节点订阅聚合与发布系统**（MIT，上游提交 `87ade36a` 起 fork，逐步重写）。

- 从 **18 个用户选定、用户授权的公开源**拉取节点订阅；
- 拉取 → 解析 → 全配置去重 → TCP 预筛 → 公平候选分配 → Mihomo 真实连通测试 → 质量排序 → 输出发布；
- 通过 GitHub Actions 定时构建，结果发布到 GitHub Pages；
- 面向用户（引流）的体验设计：节点重命名为「国旗 + 中文地区 + 编号 + 频道后缀」，自动生成策略分组；
- 产出 NAS 可读的 `report.json`（北京时区、地区分布、构建摘要），供后续 NAS/Telegram 自动化读取。

**关键决策历史（用户拍板）：**
| 决策 | 说明 |
|---|---|
| 单仓库单源架构 | 复用现有项目改造，不做新框架 |
| 公开源全部用户选定 | 每一批源 URL 均由用户提供并授权 |
| 频道后缀 | ` | tg@zzyyffxx`，由 `BRANDING_SUFFIX` 注入，源码不写死 |
| 关闭下载测速 | 用户观察到云端测速失败，改为只做 TCP+Mihomo 连通验证 |
| 取消国家配额 | 用户指示「有多少放多少」，输出上限 500 |
| 公开 README 不透露来源 | 主页只保留订阅链接与通用说明 |

## 3. 数据流程（管线）

1. **动态发现（可选）**：每轮从 `config/telegram_channels.yaml` 的 RSSHub 主/备实例读取公开频道消息，提取 HTTP(S) 链接；按消息发布时间保留 24 小时，状态存 `.work/dynamic-sources.json` 并经 Actions Cache 持久化。RSS 失败时保留未过期条目；动态链接不写入 Git，也不进入公开 `report.json`。
2. **拉取**：`fetch_sources` 并发拉取静态源与动态候选，单源失败不中断（只记 HTTP 状态码/异常类，脱敏）。
3. **解析**：`parsers.py` 解析 Clash YAML、URI(Base64)、纯 URI 文本；动态链接连续两轮解析不到节点将从状态池移除。订阅内的非法控制字符（部分源名称被写坏）会在 YAML 解析前替换为空格，避免整份配置被丢弃。
4. **去重**：`Node.canonical_key()` 忽略显示 `name`，对全部连接参数（含 `dialer-proxy`、SNI、Reality 等）做规范化 JSON 全配置去重。
5. **TCP 预筛**：按 `(server,port)` 分组，每端点一次连接，超时 2000ms（`TCP_CONNECT_TIMEOUT_SECONDS`），失败视为该节点不可达；畸形主机名（`UnicodeError`/`ValueError`）按节点级失败处理，不中断全流程。
6. **公平候选分配**：`_fair_candidate_selection` 每源先保 1 个，再按权重轮转，总候选 `MAX_MIHOMO_CANDIDATES=5000`；低产出源（3 次连续 `alive/tested<2%`）权重降为 0.25。
7. **Mihomo 验证**：把候选写入临时 Clash 配置，驱动 Mihomo 逐节点测延迟（`https://cp.cloudflare.com/generate_204`，5000ms 超时，`BENCHMARK_WORKERS=32` 并发）；通过者再并发做出口 IP/国家识别（`GEOIP_LIMIT`，生产为 0=全部）。
8. **质量排序截断**：按 速度(如有)→延迟 排序，`_select_output_nodes` 直接截断到 `MAX_OUTPUT_NODES=500`（无国家配额）。
9. **输出**：临时目录生成 → Mihomo `-t` 校验 → 原子替换发布目录（`clash.yaml` 最后替换）；空输出直接拒绝，保留上一份。

## 4. 配置

### 4.1 源列表 `config/sources.txt`
- 一行一个 HTTPS URL，`#` 注释允许。
- 当前 29 个源，全部由用户提供并授权；**不新增未经用户确认的源**。
- 源质量状态：`_update_quality_state` 写 `.work/source-quality.json`（环境变量 `SOURCE_QUALITY_STATE` 可改），云端经 Actions cache 持久化（key `source-quality-<repo>-`），本地在 `WorkDir` 下。

### 4.2 动态 Telegram 来源 `config/telegram_channels.yaml`
- 配置三个公开频道的 RSSHub 主/备路由；每条消息中提取的 HTTP(S) 链接按发布时间保留 24 小时。
- 动态状态文件 `.work/dynamic-sources.json` 由 Actions Cache 维护，**不提交 Git**，过期条目自动淘汰；RSS 暂时不可用不会清空仍未到期的条目。
- 动态链接必须经过现有订阅解析；连续两轮解析不到支持节点会淘汰。它们不单独写入公开 `report.json`。

### 4.3 频道后缀 `config/branding.yaml`
```yaml
branding:
  suffix: " | tg@zzyyffxx"
```
云端实际以环境变量 `BRANDING_SUFFIX` 注入（安装为包后相对路径失效，见 §7 历史坑）。

## 5. 输出产物与公开地址

Pages：`https://xxs-pickle.github.io/node_engine/`（build_type=workflow，Actions 发布）

| 文件 | 说明 |
|---|---|
| `clash.yaml` | 主订阅：500 节点、8 分组、规则 `MATCH,🎯 手动选择` |
| `v2ray.txt` | Base64 编码的 v2ray 链接 |
| `v2ray-raw.txt` | 明文 v2ray 链接（节点名已替换） |
| `report.json` | NAS 可读摘要（见下） |

**命名规则**：`国旗 + 中文地区 + 两位数编号 + 空格 + 后缀`，例：`🇺🇸 美国 01 | tg@zzyyffxx`；未知地区 `🌐 未知 NN`。

**分组结构**（8 组）：
- `🎯 手动选择`（select，含所有组 + DIRECT）
- `🚀 自动优选`（url-test，Cloudflare 204，interval 300，tolerance 100）
- `⚡ 速度优选`（select：自动优选 + 有测速结果的节点）
- 重点地区组（动态取节点最多的地区，最多 12 个）
- `🌐 其他国家`（非重点地区合并选择组，节点名保留各自国家）
- `🌐 全部节点`（select）

**report.json 结构**（NAS schema）：

## 6. GitHub Actions

| 工作流 | 触发 | 职责 |
|---|---|---|
| `dispatcher.yml` | `17 */3 * * *`（每 3 小时）+ `0 23 * * *`（北京 07:00 每日）+ `workflow_dispatch` | 选择本地/云端 runner |
| `build.yml` | 派发后 | 本地 Windows 构建（含 TCP 预筛） |
| `cloud-build.yml` | 派发后 | Ubuntu 云构建 + `upload-pages-artifact` + `deploy-pages` |
| `fallback.yml` | 调度回退 | 兜底触发 |

要点：
- Pages 必须保持 `build_type=workflow`（API PUT `{"build_type":"workflow"}`），否则 legacy 模式会用根目录重建覆盖产物（曾导致 404）。
- `actions/cache` 持久化 `.work/source-quality.json` 与 `.work/dynamic-sources.json`（restore 在 build 前，save 在 `always()` 后）；动态链接不入 Git 历史。
- 手动触发时**必须传完整 40 位 SHA**；短 SHA 会被 checkout 当 ref 模式导致失败。
- `cloud-build.yml` 权限：`pages: write`、`id-token: write`。

## 7. 本地运行与测试

```powershell
# 终端为 GBK，先设置 UTF-8，否则中文/emoji 报 UnicodeEncodeError
$env:PYTHONUTF8='1'; $env:PYTHONIOENCODING='utf-8'
[Console]::OutputEncoding=[Text.UTF8Encoding]::new($false)

# 单元测试（src-layout 需 PYTHONPATH）
cd D:\VS_Code\fnos-related\node-engine
$env:PYTHONPATH='src'; python -m pytest tests -q     # 期望 53 passed, 14 subtests

# 本地全流程（模拟云端；见 scripts/test_local.ps1，可传 -EnableSpeedTest 等）
powershell -File scripts/test_local.ps1

# 语法与差异检查
python -m compileall -q src tests
git diff --check
```

**历史坑（不要重犯）：**
1. 包安装后 `Path(__file__).resolve().parents[2]/config/branding.yaml` 指向 site-packages → 改为环境变量 `BRANDING_SUFFIX`。
2. TCP 预筛遇畸形主机名抛 `UnicodeError: label too long` → catch `(OSError, TimeoutError, UnicodeError, ValueError)`。
3. GBK 控制台打印 emoji → 先设 `PYTHONUTF8`/`PYTHONIOENCODING`。
4. 测速失败曾误杀延迟可用节点 → 失败只记 `metadata["speed_test_failed"]`，节点保留。

## 8. 运维手册

- **改源**：编辑 `config/sources.txt` → `PYTHONPATH=src python -c "from subbench.sources import fetch_sources, parse_document; ..."` 预检 → pytest → 提交推送。**只加用户明确提供的源。**
- **手动触发**：GitHub → Actions → Select local or cloud runner → Run workflow，填**完整 SHA**。
- **看构建日志**：Actions 页 → 对应 run → cloud build job（日志含 TCP kept / tested / alive 统计）。
- **排查 404**：`https://xxs-pickle.github.io/node_engine/clash.yaml` 404 时，检查 Pages 设置 build_type 是否被重置为 legacy；重新 PUT `{"build_type":"workflow"}` 后重跑构建。
- **看源质量**：`report.json` 的 `source_stats`（parsed/deduped/tcp_alive/mihomo_alive）+ `.work/source-quality.json` 的 `low_yield_streak`。

## 9. 已知问题与未决事项

1. **安全**：曾在聊天中暴露的 GitHub PAT（`XXS-pickle` 账号）**必须由用户轮换**；本地凭据已用 `git credential reject` 清除。
2. **客户端可用性未证明**：云端 Mihomo 通过 ≠ Loon/客户端通过（网络环境、协议兼容不同）。参考过 `beck-8/subs-check`（GPL-3.0，仅借鉴「合并→存活→测速→收集」思路，未复制代码）。如要提升客户端可用率，下一步可加：多延迟探测地址、协议级兼容性统计、失败分类。
3. **NAS/Telegram 集成**：用户侧后续工作；`report.json` 已提供 NAS 可读 schema（`subscription_url`/`channel_url`/regions）。
4. **隐私**：公开 README 不含节点来源；源 URL 仅存在于 `config/sources.txt`（公开仓库内，用户自行决定）。
5. **上游差异**：不再保留上游多分组/国家改名/YouTube 提取/解密等功能；本 fork 仅保留拉取-去重-验证-输出核心。
